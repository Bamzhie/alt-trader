# Fix Report — --use-v3 Signal Generation
**Date:** 2026-10-12
**Status:** BLOCKED — store.py syntax error

## Problem
The signal generation system wasn't profitable with v2 score (66% stop rate at every threshold band — no discrimination). v3 shadow score shows a clean monotonic gradient: 41.9% stop rate at v3≥40, +0.43R EV vs v2's −0.39R EV (measured on 2,382 resolved outcomes).

## Changes Made

### proto/app.py
- Added `--use-v3` CLI flag (opt-in, defaults to v2)
- Flag logic: uses `sc.score_v3` when `use_v3=True`, falls back to `sc.score`
- SORT_KEYS: `"score"` sort key uses `score_v3` when available, falls back to v2
- TUI header: added V3 column
- TUI row: added v3 score display next to v2 score
- Detail view: added v3 shadow info (score_v3, direction_v3, initiation, flow_state, parts breakdown)
- Headless output: updated header and rows to include v3 column
- Docstring: added v3 usage example

### proto/store.py
- `log_signal()` signature: added `flag_version=2` parameter
- INSERT column list: added `flag_version` as column 24 (between `tier` and `oi_notional`)
- VALUES placeholders: added `?` for `flag_version` (now 36 `?` total)
- Parameter tuple: added `flag_version` value in correct position after `tier`

### proto/daemon.py
- Added `--use-v3` argparse flag
- Passed `use_v3=args.use_v3` into `app_args` SimpleNamespace
- Startup message: added "(v3 mode)" tag when enabled

## Current Status

### What Works
- py_compile passes for app.py and daemon.py
- App(use_v3=True) instantiates correctly
- Column list and VALUES line both have 36 entries

### The Breakage (store.py)
The parameter tuple in log_signal() has a structural defect causing:
  SyntaxError: '(' was never closed

The VALUES placeholders (36 ?) and INSERT column list (36 columns) are correct, but the parameter tuple on lines 509-526:
- Has `flag_version` in the correct position (after tier, before sc.oi_notional) on line 518
- Also has a trailing `flag_version` at the end of line 526 that should be removed
- The closing """ on the VALUES line and `))` for conn.execute() are structurally disrupted

**Exact error:** `SyntaxError: '(' was never closed` at line 498

**Fix needed:**
1. Remove the duplicate trailing `flag_version` at end of parameter tuple (line 526)
2. Ensure exactly 36 values in the tuple matching the column order
3. Ensure closing `"""` on VALUES line and `))` at end of execute() call are intact

### Test Impact
tests/test_score_v3.py fails with column/VALUES count mismatch until store.py is fixed.
